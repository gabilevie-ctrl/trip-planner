# v1 build plan

> Follows the superpowers convention used in polaris-events: spec first, tasks with checkboxes, tests on pure modules before UI.

**Goal:** the app described in `docs/superpowers/specs/2026-11-08-trip-planner-design.md`, runnable from a static folder and shareable by link.

**Architecture:** `src/*.js` pure modules (criteria, compute, scoring, links, state encoding) with tests; `src/views/*.js` render functions that take `(trip, ctx)` and return HTML strings plus event delegation; `src/main.js` routes on `location.hash` with plain names (`#home`, `#new`, `#t-build`) and keeps the current trip id in localStorage.

**Tech:** vanilla ES modules, Pico CSS 2.0.6 (vendored), lz-string 1.5.0 (vendored), `node --test`.

## Review focus
1. Strictest traveller limit wins and a breach is flagged, never hidden (criteria + compute tests).
2. Budget totals: per person × travellers; contingency applied once; rest and free days priced at the transit rate (compute tests).
3. A share link round-trips a trip exactly, with only letters, digits and hyphens in the hash (state tests).
4. Changing dates re-scores season fit and re-generates the itinerary without losing picks (scoring + compute tests).
5. A ski-touring trip with travel mode "drive" gets no flight steps and does get the car/fuel split and bulletin steps (criteria tests).
